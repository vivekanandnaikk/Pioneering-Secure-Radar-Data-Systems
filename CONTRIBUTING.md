# Contributing

Issues and pull requests are welcome. Please keep contributions focused, documented, and reproducible.

## Before contributing

- Check the project scope and implementation status in the README and `docs/`.
- Confirm that source code, sensor libraries, diagrams, datasets, and other assets may be used and shared under their applicable terms.
- Do not commit credentials, private keys, Wi-Fi passwords, restricted data, large datasets, or generated binaries unless explicitly intended and properly licensed.

## Pull requests

- Explain the problem and the proposed change.
- Include relevant validation steps and results; do not imply tests or experiments were run if they were not.
- Update documentation when changing project scope, hardware assumptions, data handling, methods, or reported results.
- Clearly specify the AES mode and cryptographic library used for any encryption implementation.
- Do not commit secrets or deployable private keys. Demonstration keys should be clearly marked as non-production examples.
- Support performance claims with the hardware, network conditions, packet format, sample count, metric, and evaluation procedure.

## Reports and results

Clearly distinguish implemented and verified behavior from planned work. Attribute external firmware, libraries, hardware documentation, code, assets, and figures, and document relevant license or usage terms.
